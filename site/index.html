Features

Everything the S600L exposes for the light and the image, from one native Linux app.

Ring light

Fill light and RGB ring

  • Fill light on/off and RGB ring on/off, independently.
  • Brightness control.
  • Any RGB color. The vendor app only offers 6 presets.

Live preview

See what the camera sees

MJPEG 1280×720 at ~60 fps, right next to the controls.

When you pause the preview, the camera is released, so its in-use LED goes off.

Image controls

Every image control, in one place

  • Brightness
  • Contrast
  • Saturation
  • Hue
  • Gamma
  • Sharpness
  • Gain
  • Backlight compensation
  • Exposure: auto / manual
  • White balance: auto / 2300–7500 K
  • Focus: auto / manual
  • Zoom 0–400
  • Anti-flicker 50 / 60 Hz
  • Factory reset

"Auto" switches unlock the matching manual control: turn auto exposure off and the exposure slider comes alive.

Three ways to use it

GUI, CLI and MCP server

  • emeetctl-gui — the desktop app.
  • emeetctl — the CLI, with --json output for scripts.
  • emeetctl-mcp — an MCP server, so AI assistants (Claude Code and other MCP clients) can control the light and the image.
Safe by design

Only what the vendor app sends

emeetctl only ever sends the light commands observed in the vendor app. Any opcode that was not seen in the capture is refused.

Firmware updates are deliberately unsupported, and the Device tab says so.

Then do the udev rule step.

udev rule (tarball and source installs)

The light is driven through /dev/hidraw. This rule lets your user talk to it without root.

$ sudo cp udev/70-emeetctl.rules /etc/udev/rules.d/
$ sudo udevadm control --reload
$ sudo udevadm trigger --subsystem-match=hidraw --action=change

CLI quick tour

Same controls as the GUI, scriptable. Add --json for machine-readable output.

$ emeetctl status
$ emeetctl color 123456
$ emeetctl rainbow
$ emeetctl mode warm
$ emeetctl brightness 30
$ emeetctl off rgb
$ emeetctl image set zoom_absolute 200
$ emeetctl image reset
$ emeetctl --json status

MCP server

Let your AI assistant drive the camera. Register it once with Claude Code, or with any other MCP client.

$ claude mcp add emeetctl -- emeetctl-mcp
  • get_statuslight state and device info
  • set_light_powerfill light / RGB ring on-off
  • set_light_colorany RGB color
  • set_light_modelight mode
  • set_light_brightnesslight brightness
  • list_image_controlsavailable image controls
  • set_image_controlset one image control
  • reset_image_controlsback to factory values

FAQ and camera quirks

Things the hardware does that are worth knowing.

Zoom does nothing

The camera only applies digital zoom in MJPEG below 1080p. Measured frame by frame:

Zoom worksMJPEG 2560×1440, 1280×960, 1280×720, 1024×576, 960×720, 800×600, 640×480, 640×360
Zoom ignoredMJPEG 1920×1080, MJPEG 3840×2160, and every YUYV mode

EMEET's own FAQ also says the field of view is fixed at 4K and 1080p. Check which resolution your video app is using.

Permission denied on /dev/hidraw

Install the udev rule. The .deb package does this for you.

Other EMEET models?

Only the S600L (USB 328f:00ef) has been tested. Contributions with USB captures from other models are welcome on GitHub.

How was the protocol found?

By passive USB capture of EMEET Studio 2.0.4 (firmware 1.0.19). No decompilation.

The frame format:

090202OPLLLLLLLLdata

No checksum, with SET/GET pairs for power, color, brightness and mode. Full write-up in the README.
